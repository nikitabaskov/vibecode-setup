# 🛠️ Руководство по Matt Pocock Skills (`mattpocock/skills`)

**Matt Pocock Skills** — это экосистема узкоспециализированных навыков для AI-агентов (Claude Code, Cursor, Cline), созданная Мэттом Пококом (создателем *Total TypeScript* и ex-инженером Vercel).

### 💡 Главная философия
Переход от хаотичного «вайб-кодинга» к **системной инженерной дисциплине**. Агент не пишет код наугад по нечетким промптам, а последовательно проходит фазы разработки профессионального инженера: *Допрос требований ➔ Спецификация ➔ Декомпозиция ➔ TDD ➔ Двухосевой Код-ревью*.

---

### ⚡ Быстрая установка

Внутри Claude Code выполните команды:
```text
/plugin marketplace add mattpocock/skills
/plugin install mattpocock-skills@mattpocock
```

---

### ⚙️ Шаг 0: Первичная настройка репозитория

Перед первым использованием в новом проекте запустите мастера инициализации:

```text
/setup-matt-pocock-skills
```

Агент проведет быструю настройку и автоматически создаст 3 конфигурационных файла в папке `docs/agents/`:
1. **`docs/agents/issue-tracker.md`** — указывает, где хранятся задачи (GitHub Issues, GitLab, Linear или локальные файлы в `.scratch/`).
2. **`docs/agents/triage-labels.md`** — настраивает метки статусов (`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`).
3. **`docs/agents/domain-docs.md`** — указывает путь к глоссарию и доменной документации (например, `CONTEXT.md`).

---

### 🔀 Два типа вызова скиллов (Invocation Modes)

Скиллы Мэтта Покока делятся на две категории по способу их активации:

1. **User-invoked (Вызываются вами через `/`):** Вы явно запускаете эти команды в терминале, когда переходите на следующий этап задачи.
2. **Model-invoked (Автономные):** Агент запускает их самостоятельно, когда определяет, что перед ним подходящая задача (например, при поиске бага или написании тестов).

### 🔄 Главный сквозной пайплайн разработки (Idea ➔ Ship)

Для создания любой новой фичи рекомендуется использовать следующий цепочечный процесс:

```text
[ //mattpocock-skills:grill-with-docs ] ➔ [ //mattpocock-skills:to-spec ] ➔ [ //mattpocock-skills:to-tickets ] ➔ [ tdd ] ➔ [ code-review ]
```

#### 1. Уточнение требований (`/grill-with-docs` / `/grill-me`)
* **Тип:** User-invoked
* **Зачем:** Не дает агенту писать код по нечетким идеям.
* **Как работает:** Клод устраивает разработчику «допрос с пристрастием»: задает острые вопросы по границам фичи, техническим ограничениям и крайним случаям (edge cases), параллельно обвязывая ответы с файлом `CONTEXT.md`.

#### 2. Спецификация (`/to-spec` / `/to-prd`)
* **Тип:** User-invoked
* **Зачем:** Фиксирует ТЗ и архитектурные решения до написания кода.
* **Как работает:** Берет контекст беседы и код репозитория и автоматически создает жесткую спецификацию (PRD): описание проблемы, User Stories, границы тестов и решения, публикуя ее в ваш трекер задач.

#### 3. Декомпозиция (`/to-tickets`)
* **Тип:** User-invoked
* **Зачем:** Разбивает фичу на небольшие рабочей кусочки.
* **Как работает:** Декомпозирует спецификацию на асинхронные вертикальные срезы (tracer-bullet tickets) с понятной цепочкой зависимостей и графом блокировок.

#### 4. Разработка через TDD (`tdd` / `implement`)
* **Тип:** Model-invoked / User-invoked
* **Зачем:** Гарантирует надежный код без регрессий.
* **Как работает:** Реализует фичу строго по циклу Test-Driven Development:
  1. Пишет падающий юнит-тест на требование.
  2. Пишет минимально необходимый код для прохождения теста.
  3. Делает аккуратный рефакторинг.

#### 5. Двухосевое код-ревью (`code-review`)
* **Тип:** Model-invoked
* **Зачем:** Глубокая проверка кода перед мёрджем.
* **Как работает:** Запускает параллельно **двух независимых субагентов** в изолированных контекстах:
  * **Субагент Standards:** проверяет соответствие кода стилю и антипаттернам (`CODING_STANDARDS.md` / Fowler smells).
  * **Субагент Spec:** проверяет, выполняет ли код ровно то, что было зафиксировано в исходном тикете/PRD.

### 🛠️ Вспомогательные скиллы на каждый день

* **`/mattpocock-skills:ask-matt`** — интерактивный помощник, у которого можно спросить: *«Какой скилл из набора мне лучше использовать под текущую задачу?»*.
* **`/mattpocock-skills:diagnosing-bugs`** (Model-invoked) — системная отладка по жесткому алгоритму: *Наблюдение ➔ Воспроизведение тестом ➔ Гипотеза ➔ Правка ➔ Валидация*.
* **`/mattpocock-skills:research`** (Model-invoked) — проведение глубоких исследований исключительно по первичным источникам (исходникам, официальной документации) с выгрузкой отчета и ссылок.
* **`/mattpocock-skills:prototype`** (Model-invoked) — быстрое построение одноразового прототипа для проверки сложных вопросов состояния или UI.
* **`/mattpocock-skills:improve-codebase-architecture`** — анализ и рефакторинг кодовой базы для улучшения читаемости и тестируемости агентами.
* **`/mattpocock-skills:handoff`** — сжатие текущего контекста диалога в чистую выжимку для передачи задачи в следующую сессию без потери прогресса.
* **`/mattpocock-skills:resolving-merge-conflicts`** — безопасный авто-разбор конфликтов слияния git-веток.

### 💡 Пример полного рабочего сценария (Пример использования)

Вот как выглядит разработка новой фичи на практике:

1. **Инициализация проекта (один раз):**
   ```text
   //mattpocock-skills:setup-matt-pocock-skills
   ```
2. **Обсуждение идеи:**
   > *«Я хочу добавить автокомплит в форму поиска. Проведи со мной интервью через `//mattpocock-skills:grill-with-docs`»*
3. **Создание ТЗ и задач:**
   > *«Отлично, теперь переведи результаты в спецификацию через `//mattpocock-skills:to-spec` и нарежь задачи через `//mattpocock-skills:to-tickets`»*
4. **Разработка:**
   > *«Возьми первый тикет и реализуй его»* *(Агент сам активирует `tdd`)*.
5. **Проверка:**
   > *«Проведи `code-review` моих изменений с веткой main»* *(Агент запустит параллельных субагентов для проверки)*.
